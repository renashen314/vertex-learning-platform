# 05 — Course detail page, wired to seeded Sanity content

## Goal

Build the course detail page at `/courses/[slug]`, reproducing
`design/vertex-course.png` exactly on desktop and adapting sensibly down to
mobile, reading entirely from the live Sanity `production` dataset through the
existing server-only read layer.

Explicitly out of scope: the `/courses` catalog page, the lesson page, real
learner progress, bookmarks, search, and analytics.

### The icon mismatch

`workflow`, `rocket`, `puzzle`, and `code` appear in the dataset but not in the
schema's `options.list`, so TypeGen emits a union that excludes them and the
generated type lies about the data. Same class of problem prompt 04 fixed for
`duration`, and the same resolution: the seed files are not edited, the schema
moves to match the data. The list becomes the union of both sets (11 keys) and
the frontend supplies a glyph for each.

## Decisions and assumptions

1. **Route is `app/courses/[slug]/page.tsx`**, a server component, statically
   parameterised from `COURSE_SLUGS_QUERY` and calling `notFound()` on a miss.

2. **Progress is presentational and reads 0%** — confirmed with the user. No
   `progress` document, no server write route, no Clerk read. The sticky footer
   is built exactly as designed but driven by a `percentComplete` prop the page
   passes as `0`. Nothing is invented: at 0% the CTA reads **Start Learning**,
   and above 0% it reads **Continue Learning**, so the component is already
   correct once progress lands.

3. **Links point at routes that do not exist yet** — confirmed with the user.
   The breadcrumb's "All Courses" links to `/courses`, and lesson rows and both
   CTAs link to `/lessons/[slug]`. Those 404 until their own phases ship. Listed
   under "Needs your attention".

4. **The instructor is not rendered.** AGENTS §8 says to surface the instructor
   on the course, but the reference image shows no instructor anywhere on this
   page, and §3 makes the image the source of truth. The query already returns
   the instructor, so adding the block later is a render-only change. Flagged.

5. **The module accordion expands to show that module's lessons.** The design
   only shows the collapsed state with a chevron; lessons are the only sensible
   content behind it, and the query already carries them. Each row shows the
   derived `Lesson {m}.{n}` label, title, duration, and a FREE PREVIEW pill.

6. **"Show all N modules" renders only when there are more than 6 modules.**
   The design shows 6 of 12 with the expander. Every seeded course has 4
   modules, so the expander will not appear against current content — that is
   the data, not a missing feature.

7. **Typography follows the design system, not the mock's rendering.** The mock
   image renders every string in a serif because of a font fallback in whatever
   produced it; the design-system sheet is explicit that Playfair is Display 1/2
   only. The course title uses `font-display`; everything else is Inter, which
   is also what the shipped home page does.

8. **Derived numbers stay derived.** Total duration, module count and lesson
   count come from the query's `math::sum` / `count` projections. Module
   duration likewise. Nothing is stored twice.

9. **Shared formatting moves to `lib/format.ts`.** `formatDuration` moves out of
   `sanity/lib/lesson-position.ts` (which is about position, and where it does
   not belong) and is joined by `formatStudentCount` (`18240` → `18.2k`) and
   `formatLevel` (`intermediate` → `Intermediate`). It has no importers today,
   so the move is free.

10. **Shared icons and page chrome are extracted rather than copied a third
    time.** `components/ui/icons.tsx` becomes the canonical SVG set, and
    `app/page.tsx` and `components/ui/card.tsx` import from it instead of their
    private copies. The crosshatch background and the decorative bottom bars
    likewise move to `components/ui/`. Every value is preserved verbatim, so the
    home page must render pixel-identically — that is an acceptance criterion,
    not an assumption.

11. **`Badge`'s `popular` variant is corrected** to a pale peach chip with
    orange text, matching both the design system and the mock. The `video` and
    `lesson` variants are equally wrong against the design system but are not
    used on this page, so they are left alone and flagged.

12. **Cover image**: the design's cover is a rounded portrait-ish tile
    (280×330). Rendered with `next/image` `fill` inside an `aspect-[28/33]`
    container and `object-cover`, sourced through `urlFor`. Seeded covers are
    16:9, so they crop — correct behaviour, not a defect.

## Requirements

**Route**
1. `export default async function Page(props: PageProps<'/courses/[slug]'>)`,
   awaiting `props.params`. No `params` type written by hand.
2. `generateStaticParams` from `COURSE_SLUGS_QUERY`, filtering nulls.
3. `generateMetadata` sets title from the course title and description from its
   summary; falls back to a generic title when the course is missing.
4. `notFound()` when the query returns null.
5. Data is fetched once, through `sanityFetch`, with
   `tags: ['course', 'lesson']` so a later webhook can revalidate either.
6. Every component under `components/course/` is a server component except the
   accordion, which is the only piece that needs state.

**Layout, against the reference image**
7. Page uses the crosshatch background across its whole height; content is a
   centred container at the design's width, with the `SiteNav` (user controls
   on) above and `Breadcrumbs` (`All Courses` → course title) below it.
8. Hero: cover tile on the left; on the right the POPULAR pill (only when
   `popular` is true), the title as Display 1 in Playfair, the summary, a meta
   row of level / total duration / module count / student count each with its
   icon, then the primary CTA and a tertiary Bookmark button.
9. "What you'll learn" is a bordered panel containing a 2-column grid of
   outcome cards, each with a large outlined orange glyph, a title, and a
   description.
10. "Course Content" header carries a right-aligned "N modules · Hh Mm" summary.
11. Module rows: numbered outlined circle joined by a vertical connector line,
    title, summary, right-aligned module duration, chevron. The connector does
    not extend past the last row.
12. Sticky footer bar pinned to the bottom of the viewport, above the decorative
    bars: "Your Progress", "N% complete", the progress bar, and the CTA. The page
    reserves bottom padding so no content hides behind it.

**Behaviour**
13. The accordion toggles per module, is keyboard operable, and carries
    `aria-expanded` / `aria-controls`; the chevron rotates on open.
14. Expanded modules list their lessons with derived `Lesson {m}.{n}` labels,
    linking to `/lessons/{slug}`.
15. Both CTAs link to the first lesson of the first module. When a course has no
    lessons, they render disabled rather than linking nowhere.
16. Bookmark is a non-submitting presentational button with an
    `aria-label`, per AGENTS §7's presentational-only surfaces.

**Responsive**
17. Desktop matches the reference exactly. Below `md` the hero stacks with the
    cover above the text and the CTAs go full width; the outcomes grid drops to
    one column; the module row's duration and chevron stay on the row while the
    summary wraps; the sticky bar stacks the CTA beneath the progress.
18. No horizontal scroll at 375px.

**Data honesty**
19. Every number and string on the page comes from the query. The only literals
    are labels ("What you'll learn", "Course Content", "Your Progress") and the
    0 that stands in for absent progress.
20. Nullable fields degrade rather than crash: a missing cover renders a neutral
    tile with the course initial, a missing student count hides that meta item,
    a missing outcome icon falls back to a default glyph.

## Security considerations

- The page is a server component; the read token stays inside the `server-only`
  client. Nothing new imports `sanity/lib/client` or `sanity/env` from the
  browser.
- The accordion is the only client component and receives plain serialisable
  props — module titles, summaries, durations, lesson slugs. No image builder
  and no Sanity client crosses the boundary.
- No writes, no route handlers, no tokens introduced. Bookmark and progress are
  inert.
- Image sources stay constrained to the existing `cdn.sanity.io` remote pattern;
  no new host is added.
- Lesson and course slugs are interpolated into `href`s only, never into GROQ —
  the slug reaches the query as a bound `$slug` parameter.

## Acceptance criteria

1. `/courses/nextjs-app-router-in-depth` renders the full page from live Sanity
   content, matching the reference image on desktop.
2. All 10 seeded courses render; each shows 4 modules, 12 lessons, 4 outcomes,
   and a duration that equals the sum of its lessons.
3. A course with `popular: false` shows no POPULAR pill.
4. An unknown slug 404s.
5. Every learning-outcome icon in the dataset resolves to a real glyph — no
   fallback is hit for seeded content.
6. The sticky bar reads "0% complete" with a "Start Learning" CTA.
7. Expanding a module reveals its lessons with correct `Lesson m.n` labels.
8. The home page at `/` is visually unchanged after the icon/background/bars
   extraction.
9. `sanity.types.ts` regenerates with an 11-member icon union and no `unknown`
   result types.
10. Type check, lint, and production build all pass.
11. No horizontal scroll at 375px, and the page is usable with the keyboard.
